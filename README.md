# Мониторинг Kubernetes: лабораторная №1

Учебный проект по дисциплине «Методы искусственного интеллекта», связанный с диссертацией «Разработка мультимодальной системы мониторинга Kubernetes».

[Ноутбук лабораторной №1](notebooks/lab01.ipynb) посвящён инструментам Data Science и учебному примеру Iris из методички и первичному анализу метрик одного реального сбоя RCAEval RE2-OB. Модели не обучаются; логи и трассировки оставлены для следующих работ. Kubernetes и Docker не требуются.

RCAEval — бенчмарк диагностики первопричин сбоев микросервисных систем. RE2-OB содержит телеметрию Online Boutique, демонстрационного интернет-магазина. Выбор сценария производится из официального индекса, с приоритетом CPU stress и обязательным наличием отсчётов до и после внедрения.

## Окружение и запуск в VS Code

Нужны Miniconda, VS Code и расширения Microsoft Python и Jupyter. Для первого запуска необходим доступ к Hugging Face и conda-forge; последующий анализ работает по локальным данным.

В терминале из корня проекта:

```bash
conda env create -f environment.yml
conda activate rcaeval-ai
```

Откройте корневую папку в VS Code. В команде **Python: Select Interpreter** выберите Python 3.11 окружения `rcaeval-ai`. Откройте [notebooks/lab01.ipynb](notebooks/lab01.ipynb), нажмите **Select Kernel → Python Environments → rcaeval-ai**, затем **Run All**. Заполните ФИО, группу и преподавателя в титульной ячейке.

Если окружение не отображается, после активации выполните:

```bash
python -m ipykernel install --user --name rcaeval-ai --display-name "Python (rcaeval-ai)"
```

Для проверки в этой рабочей папке окружение устанавливается локально в `.conda/rcaeval-ai`, без изменения системного Python. Если оно уже создано, в VS Code можно выбрать интерпретатор `.conda/rcaeval-ai/bin/python` через **Enter interpreter path**, а в терминале активировать его командой `conda activate ./.conda/rcaeval-ai`. При переносе проекта создайте окружение заново командами выше: локальный каталог `.conda/` не включается в Git.

Для выполнения без интерфейса из корня:

```bash
python -m jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=300 notebooks/lab01.ipynb
```

Ноутбук определяет корень автоматически при запуске как из корня, так и из `notebooks/`. Файл окружения ограничивает основные версии; фактические версии запуска записываются в `reports/lab01/versions.json`.

В Conda используются пакеты `matplotlib-base`, `seaborn-base` и `nbconvert-core`: они предоставляют нужные библиотеки и выполнение ноутбука без дополнительных GUI-компонентов и экспорта в PDF.

## Данные и воспроизводимость

Учебный файл Iris загружается отдельно с [UCI](https://archive.ics.uci.edu/dataset/53/iris) в `data/raw/iris/iris.data`; повторное выполнение использует локальную копию. Загрузка и печать первых строк выполняются в отдельных ячейках. Никаких дополнительных пакетов для Iris не требуется. Учебный пример не увеличивает число сценариев RCAEval: индивидуальное задание по-прежнему использует только один.

Перед сдачей заполните в ноутбуке поля согласования индивидуального датасета, преподавателя, даты и подписи; наличие полей не означает, что согласование получено.

`huggingface_hub` загружает только `cases.parquet`, `{case}/metrics.parquet` и `{case}/inject_time.txt`. Скачивание всего набора или поднабора не выполняется. Сценарий выбирается детерминированно: RE2-OB с метриками и ненулевыми периодами до/после, предпочтительно `cpu`, затем первый по имени. При отсутствии CPU используется первый другой подходящий сценарий с сообщением.

Ревизия репозитория и выбранный идентификатор сохраняются в `reports/lab01/selected_case.json`, а контрольные суммы защищают от незаметной смены локальных исходных файлов. Этот небольшой файл следует хранить вместе с ноутбуком. Исходные данные исключены из Git.

Повторно выберите **Restart Kernel → Run All**: если файлы RCAEval и Iris уже на месте, сеть не используется. Не удаляйте `data/raw/rcaeval/` и файл выбранного сценария. Если переносите проект без данных, скачивание будет выполнено из сохранённой ревизии. При ошибке сети или отсутствии файла ноутбук выдаёт сообщение и прекращает анализ, не подменяя данные синтетическими.

Исходная таблица не изменяется: пропуски не заполняются, строки не удаляются. Для статистик бесконечности исключаются в копии; для каждой пары признаков отбираются совместные конечные значения. Unix-время отображается в UTC. `time` не включён в число метрик.

## Результаты

- Полный словарь метрик: сервис, назначение, тип хранения, смысловой тип, категория и границы интерпретации.
- Учебный пример Iris: числовой и структурированные массивы NumPy, объяснение NaN при неверном чтении меток, статистики и все шесть парных проекций.
- `00_iris_projections.png`: шесть парных проекций Iris с цветом и маркером вида.
- Таблица качества: пропуски, их доли, пустые признаки, бесконечности; отдельно дубликаты и некорректное время.
- Описательные статистики всех числовых метрик, сравнение до/после, корреляции и число совместных наблюдений.
- `01_time_series.png`: отдельные временные ряды четырёх метрик с отметкой внедрения.
- `02_histograms.png`: распределения выбранных метрик.
- `03_scatter_pairs.png`: три разные парные проекции.
- Вычисленные выводы, ограничения, ответы на контрольные вопросы и заключение.

Неизвестным показателям не приписываются единицы измерения. Изменение после внедрения само по себе не доказывает аномалию или причинность. Один сценарий не позволяет оценивать обобщающую способность будущей модели.

## Проверенный запуск

После разделения кода все кодовые ячейки (51) последовательно выполнены на Python 3.11.17 во временной копии проекта из `notebooks/` с программно запрещёнными сетевыми обращениями. Таблицы и анализ совпали с предыдущими результатами. Перед каждой кодовой ячейкой добавлено краткое описание. Графики сохранены в PNG с разрешением 180 dpi и встроены в ноутбук.

Фактически выбран `re2ob_checkoutservice_cpu_1` (CPU stress, первопричина — `checkoutservice`). Таблица содержит 1441 строку и 73 столбца: 72 числовые метрики и `time`. До внедрения — 720 отсчётов, начиная с внедрения — 721. Обнаружены 4 пропуска; полных дубликатов, повторяющихся временных меток и бесконечностей нет. Подробные выводы приведены в [анализе результатов](reports/lab01/analysis.md).

При настройке потребовалось разрешить сетевой доступ для Conda и Hugging Face и запуск локального ядра Jupyter вне ограничений песочницы. Эти ограничения среды проверки устранены; ошибок выполнения лабораторной не осталось.

В начале выполнения возможно уведомление `TqdmWarning: IProgress not found`: интерактивный индикатор загрузки недоступен без необязательного пакета ipywidgets. Оно не влияет на скачивание данных, расчёты и сохранение графиков.
